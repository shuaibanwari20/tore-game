# توره روی کلودفلر — لینک دائمی رایگان + ورود با گوگل/فیسبوک

این پوشه پورت کلودفلرِ بازی توره است: همان کلاینت، همان `game.js` و
`bots.js`، همان پروتکل وب‌سوکت — فقط سرور از Node/Back4App به
**Cloudflare Workers + Durable Objects** منتقل شده تا لینک بازی
**دائمی و رایگان** شود (آدرس `*.workers.dev` عوض نمی‌شود) و ورود با
**گوگل و فیسبوک** ممکن شود.

نسخهٔ Node در پوشهٔ اصلی پروژه دست‌نخورده می‌ماند و تا روز مهاجرت
نهایی، بازی زنده همان است.

## معماری (خلاصه)

- **Worker** (`src/worker.js`): صفحهٔ بازی را از فایل کامیت‌شدهٔ
  `cloudflare/dist-client.html` در همین ریپو می‌گیرد (از آدرس raw
  گیت‌هاب) و یک نسخه‌اش را در کش لبهٔ کلودفلر نگه می‌دارد؛ فایل فقط
  وقتی سرو می‌شود که کامل بودنش ثابت شود (بیش از ۳ مگابایت و ختم به
  `</html>`) وگرنه صفحهٔ «بازی در حال به‌روزرسانی است» می‌آید — پس
  به‌روزرسانی کلاینت فقط یعنی: ساخت دوبارهٔ همان فایل، کامیت و پوش.
  مسیرهای `/auth/*` را هم اجرا می‌کند و ارتقای وب‌سوکت `/ws` را —
  بعد از بررسی کوکی نشست — به Durable Object می‌فرستد.
- **GameServer** (`src/game-server.js`): یک Durable Object واحد
  («global») که **همهٔ اتاق‌ها** را نگه می‌دارد: اتاق با کد ۴ حرفی،
  ساخت/پیوستن/اتصال دوباره با توکن صندلی (۱۲۰ ثانیه)، شروع توسط
  میزبان و پر شدن صندلی‌های خالی با ربات، تایمر ۳۰ ثانیهٔ نوبت، مکث
  نمایش دست و خلاصهٔ دور — دقیقاً مثل سرور Node. تایمرها با **آلارم**
  Durable Object کار می‌کنند و وضعیت اتاق‌ها در storage ذخیره می‌شود
  تا بعد از خواب/ریبوت سرور، بازی از همان جا ادامه یابد.
  ⚖️ موازنه: یک آبجکت واحد برای مقیاس دوستانهٔ این بازی کافی و ساده
  است؛ سقف هم‌زمانی کل بازی به همان یک آبجکت محدود می‌شود. اگر روزی
  بازی بزرگ شد، قدم بعدی یک آبجکت برای هر اتاق است.
- **ورود** (`src/auth.js`): OAuth2 با گوگل (همراه PKCE) و فیسبوک؛
  نشست یک کوکی امضاشده (HMAC، ‏HttpOnly + Secure + SameSite=Lax،
  ۳۰ روز) است. وقتی `AUTH_ENABLED=1` باشد: بدون نشست، وب‌سوکت وصل
  نمی‌شود و کلاینت به‌جای منو، صفحهٔ ورود (همان سبک فرش و طلایی) با
  دو دکمهٔ «ورود با گوگل» و «ورود با فیسبوک» نشان می‌دهد؛ نام صندلی
  بازیکن به‌صورت پیش‌فرض نام حسابش می‌شود. وقتی خاموش باشد، بازی
  دقیقاً مثل امروز باز است.

## اجرای محلی

```bash
cd cloudflare
npm install
cp .dev.vars.example .dev.vars   # مقادیر آزمایشی برای تست ورود
npm run build:client             # ساخت dist-client.html + هم‌گام‌سازی ماژول‌ها
# ورکر فایل کلاینت را از URL می‌خواند؛ در تست محلی آن را به یک سرور
# استاتیک ساده روی همین پوشه نشانه بگیر:
python3 -m http.server 8901 &    # dist-client.html روی 8901
npx wrangler dev --var CLIENT_URL:http://127.0.0.1:8901/dist-client.html
                                 # http://localhost:8787  (ورود خاموش)
npx wrangler dev --port 8788 --var AUTH_ENABLED:1 --var CLIENT_URL:http://127.0.0.1:8901/dist-client.html
                                 # ورود روشن
node test/test-open.mjs          # تست کامل بازی (ورود خاموش)
node test/test-auth.mjs          # تست‌های ورود (روی پورت 8788)
node test/gate-shot.mjs          # اسکرین‌شات صفحهٔ ورود در مرورگر
```

## قدم‌های باقی‌مانده برای آنلاین شدن (Go-Live)

دیپلوی از راه **Workers Builds** است (اتصال مستقیم داشبورد به
گیت‌هاب) — نه توکن API لازم است نه `wrangler login`؛ هر پوش به
`main` خودش دوباره دیپلوی می‌کند.

1. **حساب کلودفلر** — ساخته شده (ورود با گوگل، ایمیل تأییدشده)؛
   زیردامنه: `shuaibanwari20.workers.dev`.
2. **فایل کلاینت را کامیت و پوش کن**: در پوشهٔ `cloudflare` بزن
   `npm run build:client` تا `dist-client.html` تازه شود، بعد کامیت
   و پوش — ورکر فایل بازی را از همین فایلِ داخل ریپو می‌خواند:
   `https://raw.githubusercontent.com/shuaibanwari20/tore-game/main/cloudflare/dist-client.html`
3. **اتصال گیت‌هاب در داشبورد**: داشبورد کلودفلر ← Workers & Pages
   ← Create ← **Connect to Git** ← ریپوی `tore-game` ← تنظیمات
   ساخت: **Root directory = `cloudflare/`**، Build command =
   `npm run build` (خنثی است؛ کلاینت از پیش ساخته و کامیت شده)،
   Deploy command = `npx wrangler deploy` ← **Deploy**.
   → آدرس دائمی: `https://tore-game.shuaibanwari20.workers.dev`
4. **اپ گوگل** (برای دکمهٔ ورود با گوگل) — در Google Cloud Console یک
   OAuth client از نوع Web بساز و این آدرس برگشت را دقیقاً ثبت کن:
   `https://tore-game.shuaibanwari20.workers.dev/auth/google/callback`
5. **اپ فیسبوک** — در Meta for Developers یک اپ بساز، محصول
   Facebook Login را فعال کن و این آدرس برگشت را ثبت کن:
   `https://tore-game.shuaibanwari20.workers.dev/auth/facebook/callback`
6. **سکرت‌ها** را روی ورکر بگذار (هرگز در گیت نه): داشبورد ← ورکر
   `tore-game` ← Settings ← **Variables and Secrets** ← برای هرکدام
   نوع **Secret**: ‏`GOOGLE_CLIENT_ID`، ‏`GOOGLE_CLIENT_SECRET`،
   ‏`FB_APP_ID`، ‏`FB_APP_SECRET`، ‏`SESSION_SECRET`
   (مقدار SESSION_SECRET یک رشتهٔ تصادفی بلند بساز).
7. **ورود را روشن کن**: در همان بخش Variables مقدار متغیر متنی
   `AUTH_ENABLED` را `1` بگذار (یا در `wrangler.toml` عوضش کن و پوش
   کن تا خودش دیپلوی شود).
8. تست نهایی روی همان دامنه: ورود با هر دو حساب، ساخت اتاق، یک دور
   کامل بازی.

## نکته‌ها

- نسخهٔ کلاینت در کش لبه تا ۲۴ ساعت می‌ماند: بعد از پوشِ یک کلاینت
  تازه، ممکن است بعضی بازیکن‌ها تا یک روز نسخهٔ قبلی را ببینند (کد
  خود ورکر با هر پوش فوری عوض می‌شود). اگر عجله بود، TTL در
  `src/worker.js` ‏(`CLIENT_CACHE_TTL`) را کم کن و پوش کن.
- دامنه عوض شود، فقط آدرس‌های برگشتِ قدم‌های ۴ و ۵ باید به‌روز شوند؛
  کد از روی خود دامنه ساخته می‌شود.
- پیسینگ ربات‌ها و مکث‌ها با آلارم DO است و می‌تواند کسری از ثانیه
  با نسخهٔ Node فرق کند؛ قوانین بازی هیچ فرقی ندارد (`game.js`
  مشترک است و `sim.js` رویش سبز می‌ماند).
- سکرت‌ها و `.dev.vars` در گیت نیستند؛ `.dev.vars` فقط برای تست محلی
  با مقادیر ساختگی است.
